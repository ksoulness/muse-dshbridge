## 0. 三条铁律（先看这里）

1. **一切启停/重启/远程服务管理都走 `DeepSeek-Harness.ps1`**，不要手工 `taskkill`、不要手工 `node bin.js web`、不要手工 `schtasks /run` 去起服务。
   原因：启动器同时负责 ①端口与进程身份识别 ②提权 ③日志脱敏 ④本体生命周期互斥 ⑤远程车道独立控制。绕开它 = 状态漂移。
2. **不要在 DSH 会话（agent 会话）内部重启 3079**。DSH 用 Windows job object（`KILL_ON_JOB_CLOSE`）托管子进程，会话内起的重启进程会随实例一起被杀（2026-09-27 事故）。会话内请用 `_restart-detached.ps1`（见 §11）。
3. **登录网址里的 `?token=...` 是凭据**。不要贴群里、不要写进文档；日志已做 `token=<redacted>` 脱敏，但 `*.raw` 与 `D:\Program Files\DSH\logs\web-current.log` 仍可能含明文，按凭据处理。

## 3. 交互菜单速查（双击 bat）

状态每 **30 秒**自动刷新；任意时刻按 `0` 手动刷新。

| 键 | 作用 | 等价子命令 |
|---|---|---|
| `0` | 刷新状态 | `status` |
| `1` | 启动 | `start` |
| `2` | 关闭（结束端口 3079 上的 DSH） | `stop` |
| `3` | 重启（先关再起） | `restart` |
| `4` | 复制**本机 HTTP** 当前 token 登录网址 | `url` + 剪贴板 |
| `5` | 复制**远程 HTTPS** 当前 token 登录网址 | `url-remote` + 剪贴板 |
| `6` | 启动/修复远程接入（muse 内网 + tailscale serve） | `mcp-start` |
| `7` | 停止远程接入（保留 DSH 本体与 tailscale） | `mcp-stop` |
| `8` | 远程接入自检 | `doctor` |
| `Q` | 退出菜单 | — |

菜单模式失败时会**保留现场**并等你按回车（不会自动回主页），成功则 2 秒后自动回主页。

### 3.1 交互体验规则（2026-10-22 整改）

- **每个动作先自报家门**：按 `1`/`2`/`3`/`6`/`7`/`8` 后立刻打印 `== 正在重启 DSH 3079 ==` 之类的一行，再开始干活，不会出现"按了没反应"。
- **长动作全程有进度**：启停期间每 250 ms 轮询子进程，把 `restart-dsh.ps1` 的输出（`停止 DSH PID …`、`DSH 已就绪 …`）边跑边打出来，末尾还有一行转圈计时 `正在重启 DSH 3079… / 已用 12s（最长 120s，请勿重复按键）`。
- **一次按键只触发一次**：动作进行中/结束后都会清空控制台里排队的按键，连按不会再变成"重启好几次"。菜单也提示"请勿重复按键"。
- **超时不乱来**：启停脚本 120 秒没返回就报 `超过 120 秒未返回；未重复启动` 并交回菜单，不会再叠一次启停。
- **菜单更快出屏**：本地状态先渲染、菜单项其次、远程链路最后（远程探测最慢）。`status` 子命令端到端由 **6.2 s 降到约 2.0 s**（实测），其中菜单本地块约 0.17 s、远程块约 0.66 s。
- **"无法验证发布者"弹窗**：先检查 `Zone.Identifier`；本机曾在没有该标记时仍出现弹窗，原因尚未确定。将 `.bat` 加入 `LowRiskFileTypes` 未消除实际弹窗，已撤销。

## 6. 状态输出怎么读（`status`）

```
服务状态：运行中（端口 3079，进程 PID：7636）      ← 绿=运行中 / 黄=被外来进程占用 / 红=未运行
  ⚠️ 检测到该 DSH 由提权环境启动（命令行不可读）。建议 [3] 重启一次以统一权限…
访问地址：http://127.0.0.1:3079/
数据根（DSH_HOME）：D:\Program Files\DSH
启动日志：E:\Code\DSH\launcher\dsh-web.log
（远程接入链路 3 行：gpt 公网 / muse 内网 / codex 本地，✗ 即该项未就绪）
```

- **"由提权环境启动（命令行不可读）"**：中完整性读不到高完整性进程的命令行，启动器退化为"端口 3079 上的 `node.exe` 即 DSH"。功能可用，但建议 `[3]` 重启一次把权限统一，之后普通启动器即可完全管理。
- 端口被外来进程占用时，会额外打印 `[diag]` 三行（cmdline 长度 / 正则命中 / 身份判定），用于判断到底是"不是 DSH"还是"识别规则要更新"。

## 7. 日常操作手册

### 7.1 启动（`1` / `start`）

统一调用 `restart-dsh.ps1 -Mode Start`。先校验启动链完整、取得本实例互斥锁；已有本实例时只等待 PID 与 HTTP 就绪，不创建第二个进程。已有启停操作时明确失败，不争抢日志。命令返回 0 才算完成。

启动使用 `--profile web --no-open --port 3079`，不会打开浏览器。菜单 4/5 获取登录地址；重启后 token 会轮换。

### 7.2 关闭（`2` / `stop`）

统一调用同一脚本的 `-Mode Stop`。严格匹配 npm DSH 入口、web 和本实例端口，并在终止前复核创建时间；身份不符或不可读时拒绝停止。仅停止本体及其子进程，日志过滤器随主人退出；重复关闭成功。

远程适配器、隧道和守护开关由 `mcp-*` / `lane-*` 单独管理，不调用旧版公网钩子。要停远程接入使用菜单 7 / `mcp-stop`。

### 7.3 重启（`3` / `restart`）

统一调用默认 `-Mode Restart`。先确认 Node、DSH 入口、数据目录、PowerShell 和日志过滤器存在，再停止已核验身份的旧实例。等待端口和旧日志释放后，通过逐项 Windows 参数转义启动 Node，并启动带 `OwnerPid` 的日志过滤器。

Node 就绪须同时满足：预期 PID 存活、3079 监听属于此 PID、HTTP 返回 2xx 或 401/403。以真实时间限定 90 秒，启动进程退出立即失败；上层仅等待直接生命周期脚本 120 秒。输出写入 `_launcher-command-<PID>.log/.error.log`，避免长期后台进程持有管道而拖住调用者。

上层等待已改为**边跑边显示**：先打印 `== 正在重启 DSH 3079 ==`，再每 250 ms 把上面日志的新增行转出来（token 打码），并显示 `已用 Ns` 计时；结束后给出一行结论（完成/失败/超时）并清空排队按键，见 3.1。

### 7.4 取登录网址（`4` / `5` / `url` / `url-remote`）

读取本次启动日志中的登录地址，绕过系统代理在本机确认 HTTP 200；刚就绪时 banner 可能稍晚落盘，因此最多等待约 5 秒再给出明确失败。远程地址保留同一凭据，仅替换为既有 tailnet HTTPS 域名。

菜单把地址复制到剪贴板，CLI 按原契约打印地址。地址属于凭据，不应复制到报告、聊天或验证日志。自动验证只输出是否有效，不保存凭据内容。

### 8.2 启动 / 修复（`6` / `mcp-start`）

`Invoke-RemoteStart` 顺序：

1. **前置**：3079 必须已在监听 —— relay 是上游，否则直接拒绝（提示先 `[1]`）。
2. `1/3` **守护任务**：`Enable-ScheduledTask`（若 Disabled）+ `Start-ScheduledTask`（立即触发一次）。
3. `2/3` **等车道健康**：等 `http://127.0.0.1:18081/health` 返回 200（75 秒）。
   未就绪 → 兜底手工跑一个守护周期（`scripts\watchdog-tailnet.ps1 -Port 18081`），再等；仍失败交给任务下一分钟重试。
4. `3/3` **serve 映射**：确认 `tailscale serve status` 含 `:8443 → 127.0.0.1:18081`；缺则打印补建命令 `tailscale serve --bg --https=8443 http://127.0.0.1:18081`。
5. 打印状态，`✅ 已就绪` 或 `⚠ 仍有未就绪项`。

> 远程车道由守护任务独立自愈。启动器不调用 `on-dsh-ready/on-dsh-stop` 钩子（2026-11-11 起这些 public 钩子脚本已随公网车道归档并删除），本体重启不会修改远程车道开关。

### 8.3 停止（`7` / `mcp-stop`）

`Invoke-RemoteStop` 顺序（**只停远程栈，不碰 DSH 与 tailscale**）：

1. `Stop-ScheduledTask` + `Disable-ScheduledTask`（必须先禁，否则 1 分钟内被拉回）。
2. 杀常驻 watchdog（命令行含 `watchdog-tailnet.ps1` 的 powershell）。
3. 按「cmdline + 端口」精确杀 18081 适配器（不会误伤别处 `server.mjs`）。
4. 复查残留：`18081` 仍在 → 判失败并列出。
5. 提示：`tailscale serve` 的 `:8443 → 18081` 映射保留（配置态，无进程）。

### 8.4 自检（`8` / `doctor`）

| # | 检查 | 通过标准 | 失败含义 |
|---|---|---|---|
| 1 | DSH 3079 | 有监听 | 本体没起 |
| 2 | relay descriptor + token 文件 | 都存在 | 3079 刚启动需等几秒；或插件异常 |

## 11. 会话内重启（agent / 远程自动化场景）

为什么不能用 `restart`：DSH 用 job object 托管子进程，会话内启动的重启器会随被重启的实例一起被杀；`schtasks /create` 在受限令牌下被拒（"Access is denied"）。

**唯一受支持方式：`_restart-detached.ps1`（WMI 创建进程，父为 `WmiPrvSE`，在 job object 之外）**

```powershell
# 真实 pwsh 路径必需（WindowsApps 下是应用执行别名，CreateProcess 不能直接启动）
Invoke-CimMethod -ClassName Win32_Process -MethodName Create -Arguments @{
  CommandLine = '"C:\Program Files\PowerShell\7\pwsh.exe" -NoProfile -ExecutionPolicy Bypass -File E:\Code\DSH\launcher\_restart-detached.ps1 -DelaySeconds 90'
}
```

- `-DelaySeconds`：延迟 N 秒再动手，给自己留出"留下交接说明/保存现场"的时间。
- `-DryRun`：只打印完整计划，绝不碰 3079。
- 日志：`launcher\_restart-detached-<时间戳>.log`。
- 相关历史件：`_restart-elevated.ps1`（提权版，日志 `_restart-elevated-*.json`）、`_restart-once-manual.ps1`（一次性计划任务版）、`_upgrade-codex-*`、`_retired\` 内的三次失败尝试 —— **除 `_restart-detached.ps1` 外均视为历史件**。
- 额外硬约束（实测）：WMI 起分离进程必须用 **pwsh 7 的真实路径**（`(Get-Process -Id $PID).Path`）；**绝不**用 `powershell.exe` 5.1（带任何参数都会秒退且不写日志）。
- 已知副作用：`DSH-Health-Watchdog` 兜底重启走 `start-web-logged.cmd`，不设 `DSH_RELAY_TITLE_PREFIX=""`，会让 relay 会话标题前缀回落 `codex指派-`（双前缀复发）→ 自动拉起后应再走一次菜单系重启。

### 11.1 重启前置校验协议（AI / 自动化执行时必守）

出现重启需求且用户已同意重启时，**先校验、后动手，禁止强行重启**：

1. **自检**（只读，不执行）——判断本次能否真的由 `DeepSeek-Harness.bat` 完成重启：
   - 是否在 DSH agent 会话进程树内？（在 → `restart` 会随 job object 一起被杀，判"不能"，除非改走 §11 的 WMI 方式）
   - 前提是否满足：pwsh 7 可用、能提权（UAC/无人值守是否挡住 RunAs）、3079 占用者是否可识别（外来进程会被 `stop` 拒绝）、端口/日志是否被占住。
   - 需求是否超出 bat 能力（换端口/profile、批量改配置、跨机）。
2. **分支**：
   - 能 → 执行 bat（会话内自救走 §11），并回报结果 + 按 §14 验收。
   - 不能 → **拒绝执行**，不要变通硬重启；说明哪条判据不满足、当前实例状态，并给出替代重启方式。
3. **替代方式默认：交给 Codex 执行**（由会话外执行者跑同一条 bat 或 `restart-dsh.ps1`），附可直接粘贴的命令与验收清单；备选：用户本机双击 `3079.lnk` 菜单 `[3]`。

## 12. 故障速查（启动器已给出结论，这里给处置）

| 启动器提示 | 含义 | 处置 |
|---|---|---|
| `端口 3079 被非 DSH 进程占用（PID x：name），已拒绝关闭` | 身份校验不通过 | `netstat -ano \| findstr :3079` 核实；确认后管理员 `Stop-Process -Id x -Force` |
| `端口 3079 被其他程序保留（无监听但无法绑定）` | 端口被保留/半关闭连接 | 换端口或等 TIME_WAIT 结束；查 `Get-NetTCPConnection -LocalPort 3079` |
| `启动进程已退出，DSH 未能启动` | 子进程崩了 | 看 `dsh-web.error.log` / `.raw`；常见：`EADDRINUSE`、npm 全局包损坏、profile 补丁丢必填字段 |
| `启动超时（120 秒）` | 进程在但页面不就绪 | 看日志末尾；DSH 大版本首启可能慢；仍不行 `[2]` 后 `[1]` |
| `当前启动日志中没有登录网址` | 日志里没有 `dsh web: http` | 还没起来，或日志来源不对（§7.4 自启路径） |
| `当前登录网址尚不可用` | token 已轮换/服务未起 | 重取址；必要时 `[3]` 重启刷新日志 |
| `无法写入剪贴板` | 非交互会话 | 用 `url` 子命令直接打印，自己复制 |
| `执行失败：…` | 子命令异常 | 看 `status` 与对应日志；`doctor` 查远程 |

**会话内（agent）常见坑**：

- 会话内的 `taskkill` 只能杀"自己的"子进程树；DSH 本体是父进程，杀不掉 → 用 §11 或让用户点 `[3]`。
- 不要把启动器当"前台长任务"跑，它会等 120 秒；脚本化请用 `status`（只读、秒回）。
- 别用 `& powershell -File <会留下长命子进程的脚本> | ForEach-Object`：孙进程继承管道句柄会让调用永不返回（实测挂死 7 分钟）。启动器统一用 `Start-Process -RedirectStandardOutput + WaitForExit`。

## 13. 改启动器脚本的硬规矩

1. **先备份**：`<文件名>.bak-<yyyyMMdd-HHmm>-<原因>`（现有 `.bak-*` 都在遵守这个约定）。
2. **编码**：含中文的 `.ps1` 必须 **UTF-8 with BOM**（否则 Windows PowerShell 5.1 按 ANSI 解码，中文串变乱码 → 语法错误 → `Test-Path $var` 收到 `null` 之类的怪错）。
3. **`.cmd` / `.vbs` 只写 ASCII**（cmd 在 GBK 代码页下会误解 UTF-8 中文注释）。`D:\Program Files\DSH\scripts\*` 与远程栈里"故意 ASCII"的文件不要加中文。
4. **子命令契约不改**：`menu status start stop restart url url-remote mcp-status mcp-start mcp-stop mcp-restart lane-tailnet doctor` 是 bat / 自动化 / 文档共同依赖的接口；新增只能追加，退出码语义（0/1/2）保持。`tunnel-restart` 与 `lane-public` 已于 2026-11-11 随公网车道删除，现在执行会返回 2（不再属于契约）。
5. **（历史经验，公网车道已删）不要用 `-RedirectStandard*` 起 cloudflared**：会强制 `UseShellExecute=false`，子进程继承调用者管道句柄 → 会话挂死。日志用 cloudflared 自己的 `--logfile`。
6. **改完必须跑验收**（§14），并把本文与 `PROJECT.md` 的相关描述同步。
